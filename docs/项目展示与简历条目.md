# 项目展示与简历条目（当前可核对版本）

## 30 秒介绍

我开发了一套 AI 用户反馈与技术工单处理平台，用自己的微信小程序作试点。它管理产品资料和反馈，模型在有限的只读工具中选择检索或任务人数核对，生成有文档依据的处理建议；开发者人工核对后才会建立工单。每一步的工具、模型和错误信息都留下记录，便于复盘失败案例。

## 当前已经完成并可现场展示

- React + TypeScript 工作台：项目切换、资料录入、反馈收件箱、分析依据、执行记录和工单列表。
- FastAPI + SQLite：项目、资料、反馈、分析、工单与 Trace 持久化；历史分析刷新后可恢复，不需重新消耗模型调用。
- Docker Compose：使用多阶段前端构建、API/Web 健康检查、仅本机端口映射和 SQLite 命名卷；实际验证容器重启后数据仍可恢复。
- 受控模型工作流：先选只读工具，再生成建议；BM25 对英文词、中文单字和二元词排序并记录安全诊断；引用必须对应当前项目检索到的资料原文；模型不可用时明确降级，并记录每阶段耗时与 token 用量。
- 审批安全：无有效 AI 分析和引用时拒绝建立工单；人工可修改最终标题、填写审核备注，系统保留 AI 原建议快照与审核 Trace；重复审批不会覆盖首次决定或产生重复工单。
- 工单闭环：支持待处理、处理中、已完成的单向状态机，完成时强制填写解决说明，重复请求幂等且状态变化可审计。
- 事实与验证：固定题集 36 条，其中 30 条可回答题也用于检索回归；BM25 在这 30 题上 Recall@1 为 30/30。2026-10-24 最终发布审查通过后端 127 项、前端 7 项测试及 lint/build，CI 另执行隐私门禁和 HTTP 冒烟。

2026-10-21 使用 DeepSeek V4.1 Flash 追加真实接口复测：36/36 分析可用，逐题辅助复核 35 条符合参考、1 条待作者确认，6 条故意无答案题未编造所问数字、日期或设备结论。共 72 次请求，58,887 token，整条分析 P95 为 5.045 秒，费用未知。这是 Codex 辅助复核，不能称为作者签字的独立人工准确率。**没有真实试用者数量或业务提效数据**。完整证据见 [真实接口复测](真实接口复测-20261021.md)。
