# 一按即定试用者任务与反馈表

本表用于获取真实产品反馈。邀请同学试用前，说明：反馈仅用于作者的软件改进与求职项目展示；展示前会删除姓名、微信号、联系方式等个人信息。对方可以拒绝参与或要求删除自己的记录。不要把本表的预设任务当成实际反馈。

## 请试用者完成的任务

1. 使用「选一个人」完成一次选择；描述操作是否清楚。
2. 让三人参与，尝试配置两项任务，人数分别为 2 与 2；观察程序提示，然后改成 2 与 1 再试。
3. 在倒计时中移动已有手指，再新增或移除一个触点；描述计时表现是否符合预期。
4. 到结果页试试「再来一次」「分享结果」「返回首页」。

无需每人完成全部任务。应记录实际完成情况，不能根据任务说明推断试用结果。

## 每条反馈记录字段

| 字段 | 填写方式 |
| --- | --- |
| 记录编号 | 用随机编号，不用姓名或微信号 |
| 日期 | 实际试用日期 |
| 环境 | 微信版本、设备型号或操作系统；试用者愿意提供时记录 |
| 实际任务 | 对方真正完成的步骤 |
| 原话 | 尽量保持试用者表达，脱敏后录入平台 |
| 预期 / 实际 | 对方期望看到什么、实际看到什么 |
| 严重程度 | 作者事后标注：阻断 / 困惑 / 建议 |
| 可复现步骤 | 能复现就写清步骤；不能复现明确标记 |
| 处理耗时 | 从开始核对资料到形成处理建议的实际时间；没有测量就留空 |
| 使用许可 | 对方是否允许匿名用于项目演示和求职材料 |

## 复盘问题

- 哪个步骤第一次让你犹豫？当时你以为下一步会发生什么？
- 如果出现错误或不理解的提示，你会怎样描述给开发者？
- 哪项功能最有用，哪项看起来多余？原因是什么？
- 如果下次还要使用，你会在什么场景打开它？

录入平台前核对是否为真实试用、是否已脱敏。模拟示例必须继续使用「模拟演示」来源，不混入真实反馈统计。
