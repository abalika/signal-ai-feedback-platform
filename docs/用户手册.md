# Signal 用户手册

交付日期：2026-10-21。适用于 Windows x64 本机演示。界面、API 和数据库都在本机；默认只监听 `127.0.0.1`。

## 1. 三分钟启动离线演示

1. 把交付 ZIP **完整解压**到可写文件夹，不要在压缩包内运行。
2. 双击根目录 `start.bat`，保留出现的服务窗口。
3. 浏览器打开 <http://127.0.0.1:8010>。顶部应显示“离线演示”，服务状态为“离线固定回放”。
4. 使用完毕，在服务窗口按 `Ctrl+C`；若批处理询问是否结束，输入 `Y`。

交付包包含 Python 运行时、依赖和构建后的界面；演示不需要 Node.js、Docker、密钥或联网。首次打开自动创建 `data/offline-demo.db`，不接触原项目的日常数据库。移动文件夹前先停止服务。

若端口被占用，在项目根目录 PowerShell 运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Port 8012
```

随后访问 <http://127.0.0.1:8012>。同源服务不需要设置前端 API 地址。

## 2. 演示顺序

1. 在“反馈”选择来源为 `known-07` 的问题“任务数量的合计要满足什么条件？”。
2. 点击“播放固定演示”。检查摘要、回复、引用和执行记录。结果明确标记为固定回放，内容取自项目内固定题集，**不是实时模型回答**。
3. 核对资料依据，按需要修改最终标题和审核备注，勾选“我已核对…”，点击“确认并创建技术工单”。未勾选或标题为空时不能提交。
4. 打开“工单”，进入处理中；完成时填写解决说明。可查看保留的原建议、最终标题及状态记录。重复创建同一反馈的工单会返回原工单。
5. 回到“反馈”，选择 `unknown-01` 的真实用户数问题并播放。界面应提示无法生成有依据的分析，禁止建单。
6. “总览”的模型调用和 Token 仍为 0。“评测”页面展示的是**历史记录**，本轮离线报告通过脚本生成，二者时间和含义不同。

离线模式仅回放 `examples/eval_cases.json` 中的固定问题；任意新增问题可能显示不可用，这是预期行为。需要重置演示时，保留旧数据库并改用一个新的路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Database data/demo-new.db
```

## 3. 资料、项目与日常使用

“资料”中创建项目、添加资料；项目选择器决定当前反馈、资料、工单和指标的范围。录入反馈时标明来源，模拟数据应标注“模拟”。新建项目与录入不会触发模型调用。

真实模式的正常流程为：录入资料和反馈 → 请求 AI 分析 → 核对引用 → 人工审核 → 建单 → 更新状态并填写解决说明。当前 dsh 接口有问题，本轮按用户要求**未测试真实接口，也不将历史模型成绩当作本轮结果**。

日后接口恢复后，按 `server/.env.example` 配置被忽略的 `server/.env`，再使用 `scripts/start.ps1 -Live`，默认写入 `data/local-live.db`。此时分析可能消耗额度；真实接口验收需单独执行。不要把离线数据库用于真实模式。密钥只保存在后端环境，禁止放入前端或交付包。

## 4. 备份与恢复

优先停止服务后操作。源码版使用 `server/.venv/Scripts/python.exe`，交付版使用 `runtime/python.exe`。脚本利用 SQLite 备份 API 复制一致性快照，并执行完整性检查，**目标文件必须不存在**。

```powershell
./runtime/python.exe scripts/backup.py backup data/offline-demo.db backups/demo-20261021.db
./runtime/python.exe scripts/backup.py restore backups/demo-20261021.db data/restored-demo.db
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Database data/restored-demo.db
```

恢复通过新路径切换，原文件保留。如需回退，停服后再次以原数据库路径启动。备份可能含用户输入，请按实际数据权限保管。

## 5. 一键检查与评测

源码首次安装需 Python 3.12+、Node.js 22+ 和网络：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1
./server/.venv/Scripts/python.exe scripts/smoke.py
```

交付包可直接运行：

```powershell
./runtime/python.exe scripts/smoke.py
./runtime/python.exe scripts/evaluate.py --output work/eval-current
./runtime/python.exe scripts/evaluate.py --output work/eval-next --baseline work/eval-current/report.json
```

源码版把以上 `runtime/python.exe` 换为 `server/.venv/Scripts/python.exe`。报告目录每次必须是新目录，以免覆盖证据；打开 `report.html` 查看，`report.json` 用于下次对比。

默认评测不调用模型，使用隔离临时数据库，包含 **36 条回放流程 + 30 题检索**；同一批次同时检查建单及拒绝流程。四类失败为“检索”“证据/格式”“未知问题安全拒绝”“工作流/运行错误”。通过率是工作流门禁和固定集检索命中率，不是模型语义准确率。报告记录本机耗时、零模型成本；模型延迟和语义得分标为未测。基线题集或模式不同则拒绝比较。

默认离线验收没有真实请求；固定回放本身可复现。已有 `examples/run_eval.py` 是显式调用真实接口的采集器，不属于默认验收，运行会消耗模型额度。2026-10-21 用户确认接口恢复后，使用独立数据库追加了 36 条真实分析，已完成题即时保存并在续跑时复用。结果、逐题辅助评分和用量见 [真实接口复测](真实接口复测-20261021.md)；费用缺少网关单价，记为未知。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 服务端口占用 | 使用 `-Port 8012`；不要直接结束不明进程 |
| 页面空白或旧界面 | 刷新页面；确认地址是启动窗口的端口，ZIP 已完整解压，`app/dist/assets` 存在 |
| 源码缺少构建或依赖 | 运行 `scripts/setup.ps1`；交付包缺文件则重新解压并运行校验 |
| 离线未知题无法分析 | 使用预置 known 题演示；unknown 题用于拒绝建单验收 |
| 422 输入错误 | 按界面字段提示缩短或补齐内容；反馈最多 20000 字，资料标题 200 字、正文 100000 字 |
| 数据库繁忙/不可用 | 确认文件夹可写、不要并行启动多个实例操作同一文件；稍后刷新再试 |
| 请求超时/网络错误 | 确认本机服务仍运行；分析最多等待 155 秒，其他请求 15 秒。先刷新执行记录或工单列表确认结果，再决定是否重试 |
| 备份目标已存在 | 使用新文件名，脚本不会覆盖原备份 |
| 真实模型不可用 | 检查后端配置与供应商状态；接口不可用时仍可使用离线演示，恢复后先小批量复测 |

## 7. 交付与回退

ZIP 内的 `MANIFEST.json` 记录源码提交、运行时、依赖版本和逐文件 SHA-256。执行 `runtime/python.exe scripts/check_package.py .` 可校验文件是否缺失或被改动；运行生成的 `data/`、`work/`、`backups/` 不属于发布清单。SHA-256 用于完整性检查，不是发布者身份签名。

维护者重新打包：先运行 `scripts/verify.ps1`，提交源码，然后使用项目虚拟环境执行 `scripts/package_delivery.py`。脚本只收录 Git 跟踪源码、生产构建、当前 Python 运行时和依赖、许可及新生成的离线报告，默认输出到 `delivery/`；不会收录 `.env`、用户数据库或原始工作日志。ZIP 旁附带 `.sha256`，可用 `Get-FileHash -Algorithm SHA256 <ZIP文件>` 核对。打包需要 Windows x64 和已安装的项目依赖；目标新机器运行离线包无需安装依赖。

Git 回退点和各阶段证据见 `docs/收尾审计与验收.md`。需要回看某阶段可用 `git show <标签>:<文件>`，或 `git worktree add <新的目录> <标签>` 创建独立副本；不要直接覆盖当前未提交文件。数据回退使用上一节的备份恢复，代码回退不会自动恢复数据库。

当前定位本机单用户作品演示，没有登录和项目级权限；公网部署、多租户不在本次已验证范围。Docker 同源代理已配置，当前没有重新构建容器或验证容器内模型调用。本机真实接口恢复后的追加验收见上述报告，原离线交付 ZIP 保留原版本。
